# Промт для другой нейронки: как заставить её работать над этой игрой

Файл-шпаргалка. Скопируй блок «ПРОМТ» в чат любой модели с доступом к файлам
(или к терминалу), приложи этот репозиторий и по желанию подключи Godot-MCP.

---

## 1. ПРОМТ (копировать целиком)

```
Ты — геймдизайнер и программист Godot 4. Работаешь в существующем проекте
«Cursed Survivors» (Vampire Survivors-подобная игра). Проект уже готовый:
GDScript, автолоады GameManager/SaveManager/EventBus/AudioManager/Settings/Loc,
вся графика и звук сгенерированы процедурно (Pillow + numpy), UI строится кодом.

ГЛАВНЫЕ ПРАВИЛА
1. Не ломай то, что работает. Перед правкой прочитай файл целиком и найди все
   места, где используются изменяемые имена/сигнатуры.
2. Каждое изменение проверяй в движке, а не «на глаз». Запускай сцену и смотри,
   что получилось: скриншот, значения переменных, отсутствие ошибок в консоли.
3. Если ошибка повторилась дважды — не перебирай варианты, а читай исходник,
   документацию или полный лог.
4. Все новые строки интерфейса сразу добавляй в перевод (autoloads/loc.gd):
   английский текст — ключ, русский — значение.
5. Не добавляй внешние ассеты. Всё новое рисуется скриптом в tools/ (Pillow)
   или синтезируется (numpy в tools/audio_lib.py).
6. Пиши код в стиле проекта: типизированные переменные, короткие комментарии
   на английском, snake_case, статические хелперы UIKit/FXKit.

КАРТА ПРОЕКТА
- autoloads/ — game_manager, save_manager, event_bus, audio_manager, settings, loc
- scenes/world/ — world.gd (карты, музыка, боссы), decor.gd (реквизит), atmosphere.gd
- scenes/player/ — player.gd + классы в scripts/classes/
- scripts/weapons/ — оружие (BaseWeapon: _weapon_process, get_damage, upgrade_descriptions)
- scripts/enemies/ — base_enemy.gd (скейлинг, статусы) + конкретные враги
- scripts/items/item_database.gd — арсенал классов, пулы апгрейдов, эволюции
- scripts/ui/ — все экраны (строятся кодом), scripts/fx/ — FXKit и анимации
- tools/ — генераторы ассетов: gen_sprites.py, gen_ui.py, gen_depths.py, gen_audio.py

КАК ПРОВЕРЯТЬ
Godot: ./Godot/Godot_v4.7.2-stable_win64_console.exe
- импорт ассетов:  --headless --import --path .
- быстрый смоук:   --headless --path . --quit-after 120  (в логе не должно быть SCRIPT ERROR)
- живой запуск:    обычный запуск проекта (или Godot-MCP, см. ниже)
Через MCP (если он подключён): run_project → simulate_input → take_screenshot →
run_script (GDScript: extends RefCounted + func execute(scene_tree: SceneTree) -> Variant),
в конце stop_project, иначе правки скриптов не подхватятся.

ФОРМАТ ОТВЕТА
- Сначала 3–6 строк: что понял и что именно собираешься сделать.
- Потом правки файлов (полные пути).
- Потом «Проверено:» — конкретные факты (что запускал, что увидел, какие числа).
- В конце — один следующий логичный шаг.
Не отчитывайся об успехе, если не запускал игру.
```

## 2. Пример рабочего задания (копировать после промта)

```
Задача: добавить пятый класс — «Палач» (Executioner), тяжёлый двуручный меч.

Требования:
1. Класс в scripts/classes/executioner.gd, сцена scenes/player/executioner.tscn
   (копия ironclad.tscn со скриптом), + карточка класса в главном меню
   (CLASSES в scripts/ui/main_menu.gd) и в лавке.
2. Стартовое оружие — «Казнь» (scripts/weapons/execution.gd): медленный
   вертикальный удар по площади перед собой, на 5 уровне — добивание целей
   с HP < 25%. Эволюция с пассивкой «Кровавый камень» → «Плаха».
3. Своя пассивка класса: +2% шанс крита за уровень, +0.5% вампиризма за уровень
   (не больше 6% суммарно — в проекте жёсткий кап LIFESTEAL_CAP).
4. Иконка 64×64 процедурно: tools/gen_icons_extra.py → assets/ui/icons/execution.png.
5. Все новые строки — в autoloads/loc.gd (RU).
6. Проверить: класс стартует, оружие убивает 12 манекенов за 3 секунды,
   ошибок в консоли нет, карточка на экране прокачки появляется только у этого
   класса. Приложи скриншот экрана прокачки.
```

## 3. Как это технически «заставить исполнять»

1. **Дать агенту файлы.** Вариант A — открыть проект в редакторе, который умеет
   читать/писать файлы (Cline, Cursor, Claude Code, Codex CLI и подобные).
   Вариант B — смонтировать папку проекта и дать агенту терминал.
2. **Проверка в движке — самое важное.** Без неё агент пишет «готово» вслепую.
   Подключи Godot-MCP (в проекте уже настроен `godot-mcp-runtime`):

   ```json
   {
     "mcpServers": {
       "godot": {
         "command": "npx",
         "args": ["-y", "godot-mcp-runtime"],
         "env": {
           "GODOT_PATH": "Z:/WIBECODING/VampireSurvivors/Godot/Godot_v4.7.2-stable_win64.exe"
         }
       }
     }
   }
   ```

   После этого в промт достаточно добавить: «у тебя есть MCP godot: запускай игру,
   делай скриншоты и проверяй результат сам».
3. **Дроби задачу.** Один запрос = одна система (оружие, класс, экран, баланс).
   В конце каждого запроса проси «Проверено:» со списком фактов — так видно,
   где агент соврал.
4. **Дай эталон стиля.** Приложи 2–3 существующих файла (`scripts/weapons/sword_splash.gd`,
   `scripts/ui/pause_menu.gd`, `autoloads/loc.gd`) и напиши «делай в этом стиле».
5. **Запрети фантазии про API.** В промте есть правило: не уверен в имени метода —
   найди его в проекте (grep) или в документации, но не выдумывай.
6. **Проверяй сам.** Запусти игру, нажми 2–3 кнопки, посмотри, что числа в HUD
   и поведение совпадают с заданием. Скриншот + лог консоли — минимальный набор.

## 4. Быстрые команды, которые пригодятся агенту

```bash
# импорт ассетов после генерации картинок
./Godot/Godot_v4.7.2-stable_win64_console.exe --headless --import --path .

# смоук-тест: не должно быть SCRIPT ERROR / parse error
./Godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --quit-after 120 2>&1 | grep -E "SCRIPT ERROR|parse error"

# перегенерировать ассеты
cd tools && python gen_sprites.py .. && python gen_ui.py .. && python gen_depths.py .. && python gen_audio.py ..
```
